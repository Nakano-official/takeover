# demo-site — 架空データで全画面を行き来できるデモ（D62）

GitHub Pages に置くモック。**本物の `src/` を架空データで動かして**画面を書き出すので、
画面を直せば main に入った時点でデモも追従する。ほかの `tools/` と同じく **`clasp push` の対象外**。

```
node tools/demo-site/build.js
→ tools/demo-site/dist/index.html（画面の一覧）
```

`dist/` は `.gitignore` 済み。ヘルプは `fetch` で取り寄せるので、手元で見るときは
`file://` で開かずに簡単なサーバーを立てる（例：`npx http-server tools/demo-site/dist`）。
`file://` でも画面は開けるが、ヘルプだけ読み込めない。

## 公開のしくみ

`.github/workflows/demo-site.yml` が、main への push（`src/` やデモの道具が変わったとき）で
`build.js` を回して GitHub Pages に載せる。手動でも Actions の画面から実行できる。

初回だけ、リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする。

## 中身

| ファイル | 役割 |
|---|---|
| `build.js` | 見る人ごとに全画面を書き出す。一覧（`index.html`）・ヘルプ（`help/*.json`）も作る |
| `index.html` | 画面の一覧のひな形 |
| `demo-bar.html` | 各画面の下に出す帯。見る人の切り替え・画面一覧へ戻る・リンクのつなぎ替え・「保存されません」の知らせ |

架空データと画面の組み立ては **ヘルプ撮影の道具をそのまま使う**（`tools/help-shots/demo-data.js` と `render.js`）。
データを足すときは `demo-data.js` を直す（ヘルプの画像にも効く。決まりごとはそのファイルの冒頭）。

| 見る人（フォルダ） | 画面 |
|---|---|
| `student/` 学生スタッフ（山田 太郎） | シフト確認・欠勤連絡・欠員一覧・代行依頼への回答・マイページ |
| `candidate/` 代行候補の学生（小林 健太） | 同上（水曜2限の代行依頼が届いている人） |
| `staff/` 職員 | シフト確認・シフト入力・欠員補充管理・欠員一覧・名簿・承認・学期設定・回答・マイページ |
| `newcomer/` まだ登録していない人 | 利用登録の申請 |
| `closed/` 準備中のときの学生 | 準備中・マイページ |

USB中継の画面（`device-relay`）は人が操作する画面ではないので入れていない。

## 本番の画面との違い

- 画面の中の時計は **2026-11-10（火）9:00** から進む（架空データの週に合わせるため）
- ナビや画面内のリンク（`?page=◯◯`）は、帯のスクリプトが同じフォルダの `◯◯.html` へつなぎ替える。
  いまの「見る人」に無い画面へのリンクは、開かずに知らせだけ出す
- 欠勤連絡の `?course=`・回答の `?vacancy=` は、テンプレートで埋める代わりに URL から読む
  （差し替える箇所が見つからなければ `build.js` が止まる。画面側の書き方を変えたらここも直す）
- **ボタンを押しても保存されない**。欠勤の登録と代行依頼への承諾／辞退は、本物の処理の結果を先に作ってあるので
  押した後の表示まで本番と同じになる。そのほかの書き込みは「成功した」と返すだけで、帯が「保存されません」と知らせる

## Public に出るもの

Pages は誰でも見られる。**載るのは `demo-data.js` の架空データだけ**にすること。
実データ・本番の URL・スクリプトプロパティを入れない（ビルドはそれらを一切読まない）。
