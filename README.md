# ryukoku-support-shift

龍谷大学 障がい学生支援室の **シフト管理・欠員補充・勤怠整合性チェック** を自動化する Web システム。

学生スタッフ（ノートテイカー）のシフトを時間割としてアプリ内に常設し、欠員が出たら
人材プールから候補を自動抽出して代行依頼を送り、**最初に承諾した人へ先着で自動確定**する。

- **技術スタック**: Google Apps Script（GAS）＋ HTML Service ＋ Spreadsheet ＋ Google Chat Webhook
- **データはすべて大学 Google Workspace 内に完結**（外部DB・外部サービスへ個人情報を出さない）
- 詳細な背景・ドメイン知識は [`CLAUDE.md`](CLAUDE.md)、仕様の決定経緯は
  [`docs/decisions.md`](docs/decisions.md)、未対応の改善点は [`docs/backlog.md`](docs/backlog.md) を参照。

## 実装済みの機能

### シフト確認（時間割）— `?page=home`（全員）
- 「利用者（被支援者）中心の時間割」をアプリ内にデジタル表示（D8）
- **レスポンシブ**：PC＝曜日×時限のグリッド／スマホ＝曜日タブ＋カード
- 軸は**固定枠**（標準曜日＋時限マスタ全時限）。授業の無い時限・空きセルも枠として表示
- 各コマは**ボタン式**。タップで詳細モーダル（利用者・科目・担当教員・教室・備考・状態）
- 教室はカードに常時表示
- **絞り込み**：利用者／スタッフ（「自分」ワンタッチ）／内容（テイク・介助）
- **「あと1名 募集中」を緑表示**：テイクが1名のコマ＝恒常的な空き枠を可視化
  （当日欠勤の「欠員対応中」は赤で別表示し、色の意味を分離）
- **マイビュー**（学生）：自分の担当コマと、自分が入れる募集中の空き枠
  （スキル一致＋その時限が空き）を同じ時間割上で見比べられる（D8③）

### シフト入力 — `?page=input`（職員のみ）
- 利用者中心の時間割（`courses`）を画面から追加・削除（backlog #4）
- 利用者は**選択式**（既存名のプルダウン＋「新規追加」。表記ゆれ防止）
- 担当スタッフ欄は**選んだ曜日・時限に空きがあり、内容に対応できる人だけ**を自動表示
  （既存の空きコマ情報＋スキルで絞り込み。全員表示への切替も可能）
- 同一コマへの二重起用ガード／欠員が紐づくコマは削除不可（記録保全）

### 欠勤連絡 — `?page=absence`（全員）
- 学生・職員が欠勤を登録すると `vacancies` に欠員を起票
- 対象コマの空きスタッフを**自動スクリーニング**して代行候補を抽出
- 候補者と職員スペースへ **Google Chat（Incoming Webhook）で個別通知**

### 代行依頼への回答 — `?page=respond`（候補者）
- 通知リンクから「承諾／辞退」を回答
- **最初に承諾した候補者へ先着で自動確定**（D1。`LockService` で原子的に処理し競合を防止）
- 確定後は本人・他候補・職員へ結果を通知し、回答画面は「受付終了」を表示

### 欠員補充管理 — `?page=manage`（職員のみ）
- 欠員一覧と回答状況をダッシュボード表示
- 誰も承諾しない等の例外時に「1人テイク／職員対応」で決着

### スタッフのスキル区分（D9）
- `staffs` の `skills` 列（`テイク` / `介助` / `テイク,介助`）で対応可能な内容を管理
- 代行候補の抽出時に**コマの内容と一致するスキルの人だけ**を候補にする
  （介助しかできない人にテイクの依頼が飛ばない）

### 物理アラート端末（M5Stack）連携 — `?device=alert`（D6）
- トークンで保護した軽量エンドポイントが「未対応の欠員件数＋最新欠員番号」のみ返す（個人情報なし）
- 端末側スケッチは [`device/`](device/) 参照

## ディレクトリ構成

```
src/                GAS スクリプト（.gs）と画面（.html）
  code.js           エントリポイント（doGet・ルーティング・ロール判定）
  Vacancy.gs        欠員起票・候補スクリーニング・先着自動確定
  Input.gs          シフト入力（courses 追加・削除・候補絞り込み）
  Notify.gs         Google Chat 通知
  Sheets.gs         Spreadsheet 操作の共通処理
  Calendar.gs       カレンダー連携（機能Bの基盤）
  Device.gs         M5Stack 用エンドポイント
  Setup.js          DB初期化・ダミーデータ生成・マイグレーション
  home/absence/input/respond/manage.html  各画面
device/             物理アラート端末（M5Stack）のスケッチと手順
docs/               設計ドキュメント・決定ログ
```

## セットアップ概要

GAS プロジェクトへは [clasp](https://github.com/google/clasp) で反映する（**clasp は 2.4.2 に固定**）。

```bash
npx clasp push --force
```

初回はスプレッドシートを生成し、スクリプトプロパティを登録する。

1. GAS エディタで `setupSpreadsheets` を実行 → メインDB・連絡先DB を作成（ダミーデータ入り）
2. 生成された2つのスプレッドシートIDを **スクリプトプロパティ**に登録
   （`SPREADSHEET_ID` / `CONTACTS_SPREADSHEET_ID`、ほか `CALENDAR_ID` / `CHAT_WEBHOOK_URL` / `DEVICE_TOKEN`）
3. 連絡先DB `contacts` の自分の行の `email` を実アドレスに変更してログイン確認
4. 既存DBへ列を足す場合は `migrateCoursesColumns()` / `migrateStaffsColumns()` を実行

> 認証情報はコードに直書きせず、必ず `PropertiesService`（スクリプトプロパティ）で管理する。
> 実証実験フェーズでは実データを使わず、ダミーデータで動作確認する。

詳細なプロパティ一覧・データ設計は [`CLAUDE.md`](CLAUDE.md) を参照。
