## 2026-07-10 学期マスタ（terms）の導入 — 2体系（クォーター/セメスター）の同時進行

### D16. 「現在の学期」を文字列ソートではなく terms シート（開始/終了日）で解決する
- **背景**: backlog §11-3。「クォーター制は先端理工学部（学籍番号 **Y 始まり**）のみ、他学部はセメスター制
  （前期/後期）」という事実が判明。**2つの学期体系が同じ暦の上で同時に走る**（例：7月は「前期」と「Q2」が
  両方"現在"）。従来の `quarters.sort()` 末尾＝現在という**単一学期前提は成立しない**。
  この「最新学期」ロジックは `code.js`（getTimetable）/`Input.gs`（getInputData）/`Vacancy.gs`（getMyCourses）に
  三重複しており、表記が混ざると辞書順が壊れる地雷でもあった。
- **決定**: `terms` シートを1枚追加し、**日付で「今日を含む学期の集合」**を解決する。
  - `terms`：`term_id`／`system`（quarter/semester）／`start_date`／`end_date`。
  - 共有ヘルパー `Terms.gs`：`currentTermIds_`（今日を含む学期＝集合）／`activeTermIds_`／
    `resolveTermSelection_`（画面セレクタ解決）に三重複を集約。
- **courses 側の持ち方（ユーザー選択）**: 列名 `quarter` は**据え置き**、値に term_id（例 `2026-前期` / `2026-Q2`）を入れる。
  **term_id の値自体が体系を担う**（`Q2` か `後期` か）ため、courses に 利用学生の学部/学籍番号を持たせなくても成立する。
  → マイグレーション不要（コードはヘッダー名で読む）。
- **「現在」の扱い（ユーザー選択：日付で自動）**: `start_date`/`end_date` で判定。
  - **home（閲覧）**：既定＝「現在（開講中）」＝今日を含む学期**すべての和集合**（先端理工Qと他学部セメスターが並ぶ）。
    セレクタ先頭に番兵 `''`（現在）＋各 term_id。
  - **input（編集）**：単一学期（新規コマの割り当て先は1学期に定まるため）。現在のうち開始が最新のものを既定に。
  - **getMyCourses（欠勤選択）**：現在の学期集合に属する自分の担当コマ。
- **スコープ（ユーザー選択：モデル＋現在学期解決まで）**: 上記まで。
  **`findCandidates_` の二重起用チェックは今回対象外**（現状は `quarter` 完全一致のまま）。
  ただし terms の日付を持ったことで、将来「暦で重なる学期」での cross-system 掛け持ち検出に拡張できる
  （先端理工Q3 と 他学部後期は暦が重なるのに別termとみなし検出し損ねる潜在バグ。別パスで対応）。
- **学期の入れ子と履修登録（2026-07-10 追記）**: **前期⊇Q1+Q2／後期⊇Q3+Q4** の入れ子構造。
  履修登録は半期一括で、**春に「前期・Q1・Q2」／秋に「後期・Q3・Q4」をまとめて登録**する
  （先端理工のQ1/Q2も春に同時登録）。この事実は日付ベースの「現在＝開講中の和集合」を裏付ける
  （7月は前期とQ2が同時に現在）。terms 雛形の日付もこの入れ子で入れている。
  運用含意：空きコマ再収集は登録タイミングに揃い**実質年2回**（各回がその半期の2クォーターを含む）。
  Q1/Q2で履修が変われば空きコマも変わりうるため、available_slots を学期別に持つ必要性は Phase 3 で検討。
- **後方互換**: `terms` が未整備（旧DB）でも、`resolveTermSelection_`/`activeTermIds_` は
  **courses 由来の辞書順末尾を現在とみなす従来動作へフォールバック**する。段階移行のため
  `migrateAddTermsSheet()`（当年度の前期/後期＋Q1〜Q4の雛形を作成）を用意。
- **Setup**: ダミーデータは**実行時点を基準に相対日付**で学期を生成し、6名をセメスター前期・2名をクォーターに
  振り分けて「現在に両体系が並ぶ」状態を再現（いつ実行してもデモが空にならない）。
- **検証**: `Terms.gs` を stub 環境で駆動する合成シミュレーション18ケース全通過
  （現在集合・和集合/単一の既定・明示指定・現在なし時の最新フォールバック・terms未整備の後方互換）。
- **今後（別パス）**: 11-1（機能Bの予定側DB由来化）と組み合わせると、term×courses から予定を組めるようになる。
  スタッフ空きコマの再収集サイクル（Phase 3・学部で異なる）の基盤にもなる。
- **ステータス**: 実装済（`terms` シート・`Terms.gs` 新設、`code.js`/`Input.gs`/`Vacancy.gs`/`home.html`/`Setup.js` 改修）。

## 2026-07-10 欠員ライフサイクルの状態機械化・ステータス定数の一元化

### D15. 欠員の状態遷移を1経路（settle / reopen）に集約し、result 文字列を定数化する
- **背景**: backlog §11-2・§11-4。「未解決 → 補充済／1人テイク／職員対応 → 再オープン」の遷移が
  `respondToVacancy`・`confirmSubstitute`・`setVacancyResult`・`reopenVacancy`・自動決着に
  **ばらばらに実装**され、CAS（先着確定との競合検査）や前提条件が遷移ごとに抜けていた。
  レビュー §10 の 10-1（非アトミック確定）・10-4（再オープンで再通知されない）・
  10-9（過去日に承諾できる）は、いずれも**同じ構造が原因**（同じ穴の別の出口）。
- **決定（状態機械・11-2）**: `result` 列を「決着マーカー」とした compare-and-set を2関数に集約する。
  - `tryTransitionVacancy_(vacancyId, direction, updates)`：throwしない低レベル版。
    `direction='settle'`（空→決着＝先着確保）/ `'reopen'`（決着→空）。先着で負けても例外化しないため
    `respondToVacancy` が「埋まりました」を穏当に返せる。
  - `transitionVacancyOrThrow_(...)`：前提不成立（既に決着済み／まだ未決着／対象なし）を
    職員向けメッセージで throw する。confirm/setResult/reopen 用。
  - 全ての `result` 書き込みをこの2関数だけに通す。実体は既存の `claimIfEmpty`／`updateRowIfGuard_`
    （Sheets.gs のロック内CAS・D1）で、遷移の入口を1箇所にまとめたもの。
- **同時に解消したバグ（§10）**:
  - **10-4**：`reopenVacancy` の末尾で `notifyNewVacancy(vacancyId, true)` を呼び、候補者へ
    「（再募集）」を再送する。従来は notify_status を戻すだけで再送経路が無く無人化の恐れがあった。
  - **10-9**：`respondToVacancy` に `assertVacancyNotPast_`（対象日が過去なら throw）を追加。
    作成側 `submitAbsence` にしか無かった過去日拒否の非対称を是正。職員の手動確定（confirm/setResult）は
    後追い記録のため過去日でも許容する（候補者の古いリンク経由のみを弾く）。
- **決定（定数一元化・11-4）**: ステータス文字列を `Constants.gs` に集約する。
  `VACANCY_RESULT`（FILLED/SOLO/STAFF）・`VACANCY_RESULT_VALUES`・`COURSE_VACANCY_STATUS`（NORMAL/OPEN）・
  `ANSWER`（ACCEPT/DECLINE）・`MSG_VACANCY_SETTLED`。**値は従来と完全に同一＝挙動不変**の内部整理で、
  サーバー（Vacancy.gs・code.js・Notify.gs）の判定・分岐はこの定数を参照する。
  「休講」等の4つ目の決着区分を足す日に、多数ファイル同時修正ではなく Constants.gs 中心の追加で済む。
- **スコープ外（今回は据え置き）**: HTML（manage/home/respond）はサーバーが返す同じ文字列値を
  表示・比較しており、値不変のため未変更。テンプレート経由で画面へ定数を渡す案は将来の課題。
- **検証**: 実コード（Constants.gs＋Vacancy.gs の遷移関数）を stub 環境で駆動する合成シミュレーション
  16ケース（settle/reopen の成否・対象なし・未知遷移・過去日ガード・先着競合の縮図）全通過。
  実GASでの e2e 確認は backlog 9-5 と同枠で残。
- **ステータス**: 実装済（`Constants.gs` 新設・`Vacancy.gs`／`code.js`／`Notify.gs`／`manage.html` 改修）。
  未着手の設計提案 11-1（機能Bの予定側DB由来化）・11-3（学期マスタ）は別途。

## 2026-06-30 勤怠整合性チェック（機能B）の照合設計

### D14. カレンダー（実態反映済み）を「予定の正」とし、CSVアップロードでメモリ内照合する
- **背景**: 課題2。学生の勤怠登録（労務管理システム）に記入ミス・登録漏れが多く、職員・教務課が
  Googleカレンダーと**目視照合**して見つけている。この照合を自動化し、差分を一覧ハイライトする（機能B）。
- **突合の2本のキー経路**（D7・D2 を統合）:
  - 予定側： `カレンダー説明欄の氏名 → staffs.name → staff_id`
  - 実績側： `CSVの個人ｺｰﾄﾞ → staffs.personal_code → staff_id`
  - `(staff_id × 日付)` でグループ化し、開始/終了の時間帯を比較する。
- **CSV取り込み（ユーザー選択：画面アップロード）**:
  - `check` 画面で勤怠CSVを選択 → クライアントで base64 化 → GAS へ送信。
  - サーバー側で `Utilities.base64Decode` → `newBlob(bytes).getDataAsString('Shift_JIS')` で復号 → `Utilities.parseCsv`。
  - **ファイルもCSV内容もシートに保存しない**（メモリ内で照合し結果だけ画面に返す）。D2の「不要行を即破棄し保存しない」と整合。
- **CSVの絞り込み（D2-追記）**: `個人ｺｰﾄﾞ` が `staffs.personal_code` に在籍 ×`ｱﾙﾊﾞｲﾄ先①/②/③` のいずれかが
  `ノートテイク` の行のみ残す（他キャンパス・職員・別バイトを破棄）。①②③ブロックは全走査。
- **照合基準（ユーザー選択：カレンダー時刻を正）**:
  - 職員がイレギュラー（超過・早退・休講・代行）を反映済みのカレンダーを信頼できる「予定の正」とする。
  - 比較は**15分丸め**（出勤簿は「予定ベース＋15分丸め」で記録＝backlog #8）。丸めた開始・終了が一致なら一致扱い。
  - 早終了・超過は分単位では必ずズレるため、**「時間不一致」として出し、職員が目視で確認**する（自動では正誤判定しない）。
- **差分3型（D2-追記）**:
  - 🔴 **登録漏れ**：カレンダーに予定あり・CSVに無し（学生の登録漏れ／欠勤・休講）。最重要。
  - 🟡 **予定外勤務**：CSVあり・カレンダーに予定無し（代行で入った・超過枠など）。
  - 🟠 **時間不一致**：両方あり・15分丸めでズレ（超過・早退）。
- **要確認（突合不能）**: カレンダーの氏名が `staffs.name` に無い（表記ゆれ・D7の弱点）／CSVの個人ｺｰﾄﾞが
  `staffs.personal_code` 未登録。これらは差分とは別枠で「要確認」として列挙する。
- **データ構造への影響**: `staffs` に **`personal_code` 列を追加**（D2/D7 の積み残しを回収）。
  Setup.js のダミー生成・本番ヘッダー・`migrateStaffsPersonalCode()` マイグレーションで対応。後方互換（ヘッダー名で読む）。
- **適用範囲（このセッション）**: 照合エンジン＋`check` 画面（アップロード・期間指定・差分ハイライト）まで。
  月末リマインダー（B-3）・教務課レポート共有（B-4）は Phase 3 として後続。
- **未確認（実データ待ち）**: 実CSVの**ヘッダー文字列**（①②③ブロックの正確な列名）は Git 管理外で未入手のため、
  パーサのヘッダー定数を1か所に集約し、実ファイル入手時に調整できるようにする。氏名の表記ゆれ（D7③）も実カレンダーで要確認。
- **ステータス**: 設計確定（本エントリ）。実装着手。

## 2026-06-24 フォーム連携（空きコマ・連絡先の自動取り込み）

### D13. 学生回答は「1フォーム」、振り分けは GAS（onFormSubmit）で行う
- **背景**: 空きコマと連絡先（メール・電話・Webhook URL）を集めたいが、学生に2フォーム答えさせるのは面倒。
  一方、回答には Webhook URL（秘密）・電話（個人情報）が含まれ、保存先の権限分離も必要。
- **決定**:
  - フォームは**1つ**（セクション①空きコマ・スキル ②連絡先）。Google フォームの**セクションは保存先を分けない**ため、
    DBへの振り分けは受信側 GAS（`Forms.gs` の `onIntakeFormSubmit`）で行う（ファンアウト）。
    空きコマ・スキル→`staffs`、電話・Webhook→`contacts`。
  - 回答先スプレッドシートは**連絡先DB（職員のみ・D4）**にリンク（秘密・個人情報を含むため）。
  - **回答を ryukoku.ac.jp 組織内に制限＋メール確認済み収集**。学生＝`mail.ryukoku.ac.jp` / 職員＝`ad.ryukoku.ac.jp`
    は同一 Workspace 想定なので学生も回答可（要・学生アカウントで送信テスト）。
  - 照合は**メールをキーに contacts の名簿へ突き合わせ**、登録済み staff_id の行だけ更新。
    名簿に無いメールは反映しない（学外＝制限でブロック／学内の無関係ユーザー＝名簿で弾く、の2段構え）。
- **上書きポリシー（レビュー反映）**:
  - 空きコマ：クォーター再収集なので**毎回上書き**（未選択＝今期は空き無し）。
  - skills：空送信では**上書きしない**（空欄＝全対応扱いのため、未チェック送信で介助専門者にテイク依頼が飛ぶのを防ぐ）。
  - 電話・Webhook：入力時のみ上書き。Webhook は **Google Chat の URL 形式（`chat.googleapis.com`）のときだけ**反映。
- **設置**: `installIntakeTrigger()` を1回手動実行（回答先＝連絡先DBに `onFormSubmit` 設置）。`testIntakeMapping()` で検証。
- **ステータス**: コード実装済（`Forms.gs`）。実フォーム作成・トリガー設置・送信テストは未実施。
  フォーム自動取り込みは従来 backlog（Phase 2）だったものを前倒しで実装。

## 2026-06-23 欠員の自動決着（補充候補0人時）

### D10. 補充候補が0人なら自動で決着する（相方が残れば1人テイク／残らなければ職員対応）
- **背景**: backlog #5・レビュー #4。「もともと1名のコマ（人手不足のテイク／介助）」や、
  候補が誰もいない欠員で、補充ロジックの分岐が無く欠員が開いたまま放置される穴があった。
- **決定（ユーザー選択：A）**: 通常どおり補充を試み、**補充候補が0人なら自動で決着**させる。
  - 欠勤者を除いて**相方が残るコマ（2名テイク等）→「1人テイク」**
  - **誰も残らない1名コマ（1名テイク・介助）→「職員対応」**
  - ドメイン知識（CLAUDE.md）の「補充できない場合のみ1人テイク／1名体制の欠員は最終手段で職員対応」と一致。
- **募集人数**: 欠員＝1名ぶん。代行は**1名**を募集し、先着1名で充足（従来どおり）。
- **適用範囲（現時点）**: 候補が**作成時点で0人**のケースを自動決着する。
  候補はいるが**全員辞退/無回答**のケースの自動降格は、締切・リマインド（requirements §8・レビュー #7）の
  実装とセットで対応（本決定では未対応）。
- **実装**: `submitAbsence` で候補0人時に `result` を設定し、`notifyAutoResolved` で職員スペースへ一報。
  相方も同コマ・同日に欠勤登録済みなら「職員対応」に倒す（両者欠勤の補正）。
- **暫定であること**: 自動決着は暫定。後から代行者が見つかった等の場合、職員は管理画面の
  **「再オープン」**で未確定に戻して充て直し・結果変更ができる（`reopenVacancy`）。

## 2026-06-23 時間割のデジタル化方針

### D8. シフト確認は「利用者中心の時間割」をアプリ内にデジタル化して表示する
- **解決する課題**: 時間割（実物は静的な画像）はクォーター開始時に Google Classroom へ1度流されるだけで、
  その後は他通知に埋もれて**誰も見なくなる**。結果、本当はその時間帯が空いていてシフトに入れる学生が、
  時間割を把握していないために「どこのシフトが空いているか」を理解できていない。
  → 時間割を**アプリに常設**し、いつでもスマホで見られるようにして打開する。
- **時間割の実構造**（実物のスクリーンショットで確認）:
  - **横軸＝曜日**、**縦軸＝時限**。各時限の中に**利用学生（被支援者）ごとの行**が複数並ぶ。
  - 1コマ（利用者×曜日×時限）の情報 = `内容(テイク/介助)・利用学生・科目名・担当教員・教室・スタッフ(1〜2名)・備考`。
  - **同じ曜日・時限に複数の利用者が同時に存在**するため、単純な「曜日×時限グリッド（1マス1コマ）」では表現できない。
  - スタッフは**テイク=2名・介助=1名**のことがある。
- **静的性**: 時間割は**クォーター内では静的**（多くは半期固定）。代行・イレギュラーがあっても**時間割自体は更新せず**、
  当事者が各自で把握している運用。→ システムも「時間割は触らず、欠員・代行は別レイヤー（vacancies/responses）で管理」とし、現場運用と一致させる。
- **データ投入フロー**: クォーター毎に、被支援者がフォームで「今期の支援が必要な授業」を入力 → **職員がシフトとして登録**（人材プールの空きコマ再収集と同じリズム）。
- **画面**: ①利用者ごとの支援体制（時間割表・全員閲覧）と、②学生スタッフ各自のマイシフト確認（別画面）の**両方**を実装する。
- **データ構造への影響**: `courses` を拡張（`support_type`/`user_student`/`subject`/`instructor`/`room`/`note` を追加。`staff_a_id`/`staff_b_id` は維持、介助は `staff_b_id` 空）。
  追加カラムは後方互換（既存コードはヘッダー名で読むため欠員機能を壊さない）。backlog #1・D7 の「利用者・教室をいずれ追加」を回収。
- **ステータス**: 方針確定。Step1（courses 拡張）から実装着手。

#### D2-追記（2026-06-16 実CSV入手で仕様判明）
実際の出力CSV（Shift_JIS / ダブルクオート区切り）を入手し、上記の確認待ちが解消した。
**実データを含むため当該CSVは Git 管理外（.gitignore の `*.csv`）とする。**

- **1行＝1人×1日**。1日に最大3件のバイト枠（①②③ブロック）を持つ。
- **紐付けキー（解決）**: `個人ｺｰﾄﾞ`（例 `Y2xxxxx`・7桁の安定ID。学籍番号系）。
  氏名照合をやめ、これで突合する。→ **`staffs` に `personal_code` 列を追加する**（要 architecture.md / Sheets 反映）。
- **絞り込み（解決）**: 二段構え。
  1. `個人ｺｰﾄﾞ` が `staffs.personal_code` に存在する行だけ残す（他キャンパス・職員・無関係者を排除）。
  2. さらに `ｱﾙﾊﾞｲﾄ先①/②/③` のいずれかが `ノートテイク` の行（同一学生の別バイトを排除）。①固定ではないので①②③全走査。
- **主な列**: `個人ｺｰﾄﾞ / 氏名 / 処理日(yyyy/MM/dd) / 曜日 / 勤怠区分 / 出勤例外 / 退勤例外 / ﾒﾓ1 / ｱﾙﾊﾞｲﾄ交通費`、
  以降 ①②③ それぞれに `承認 / ｱﾙﾊﾞｲﾄ先 / 開始(HH:mm) / 終了(HH:mm) / 休憩(H:mm) / 時間(H:mm・実労) / 更新者氏名 / 更新日 / 更新時刻`。
- **照合方式への影響**: CSVに**時限（period）は無く実勤務時刻のみ**。
  機能Bは「日付＋時刻の重なり」で突合する（予定側は `periods` で時限→時刻に変換）。
- **CSVは「実際に働いた日だけ」出力される（重要）**: 予定して休んだ日（欠勤・休講・欠員）は
  **行が存在しない**＝CSVは「勤務があった」ことの陽性記録のみ。差分判定は次の3型になる：
  - **予定あり・CSV無し** → 登録漏れ／欠勤・休講（カレンダー側に予定があるのにCSVに無い）。
  - **予定無し・CSVあり** → 予定外勤務（代行で入った・超過枠など）。
  - **両方あり・時刻ずれ** → 時間不一致（超過・早退）。
  これは CLAUDE.md のイレギュラーパターン（超過/早退/休校/欠員/代行）にそのまま対応する。
- **このサンプルCSVは利用者本人の勤怠のみ**（他者データ無し）。ただし本番出力は他キャンパス等も
  混在する前提（D2本文）は変わらない。実データのため引き続き Git 管理外。
- **ステータス更新**: CSV仕様は確定。実装は `staffs.personal_code` 追加とセットで着手可能。
