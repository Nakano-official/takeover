## 2026-06-16 アドバイザー相談・本部確認

### D1. 代行者の決定方式は「先着自動確定」にする
- **決定**: 欠員の代行者は、職員が承認者を選ぶのではなく、**最初に「承諾」した候補者に自動で確定**する（先着順）。
- **背景**: 現場運用として、職員の選定を待たず最速で代行者を埋めたい。
- **影響・対応**:
  - ⚠️ これは CLAUDE.md の原則「職員が最終確定（システムは自動決定しない）」を**反転**させる変更。CLAUDE.md の記述を更新する必要がある。
  - `respondToVacancy`（承諾処理）に「承諾＝即確定」を追加。同時押しの競合に備え、`LockService` 内で「未確定か確認 → 確定」を**原子的に**行う。
  - 2番目以降の承諾は「すでに他の方が代行に決まりました」と表示して受け付けない。
  - 職員の操作は**例外時のみ**残す：誰も承諾しなかった場合の「1人テイク／職員対応」決着、確定後の取り消し・差し替え。
  - データ構造（vacancies の result / substitute_staff_id）の変更は不要。
- **ステータス**: 仕様確定。実装は未着手（CLAUDE.md 更新とセットで行う）。

### D2. 勤怠データCSVは「全部入り」。絞り込みと紐付けキーが必要
- **決定（判明した事実）**: 月末に出力される勤怠CSVには、支援室の学生スタッフだけでなく、**職員・他キャンパスの学生スタッフ・他キャンパスの職員**の勤怠も含まれる。
- **影響・対応**:
  - 機能B（カレンダー↔勤怠の突合）の前に、**「本キャンパス・支援室の学生スタッフの行だけ」に絞り込む**処理が必須。
  - 絞り込んだ行を `staffs` の誰かに**紐付けるキー**が必要。氏名照合は同姓同名・表記ゆれで事故るため避け、**学籍番号・職員番号などの安定IDが望ましい**。
  - プライバシー：無関係な他者の個人情報が混ざるため、**絞り込みで不要行を即破棄し保存しない**設計にする。
- **確認待ち**（次回まで・下記「確認待ち事項」参照）: CSVのヘッダー（列名）・サンプル、絞り込みに使える列、紐付けキーの有無、勤務日時の持ち方。
- **ステータス**: 設計方針確定。CSV仕様の確認待ちで実装着手は保留。

#### D2-追記（2026-06-16 実CSV入手で仕様判明）
実際の出力CSV（Shift_JIS / ダブルクオート区切り）を入手し、上記の確認待ちが解消した。
**実データを含むため当該CSVは Git 管理外（.gitignore の `*.csv`）とする。**

- **1行＝1人×1日**。1日に最大3件のバイト枠（①②③ブロック）を持つ。
- **紐付けキー（解決）**: `個人ｺｰﾄﾞ`（例 `Y2xxxxx`・7桁の安定ID。学籍番号系）。
  氏名照合をやめ、これで突合する。→ **`staffs` に `personal_code` 列を追加する**（要 architecture.md / Sheets 反映）。
- **絞り込み（解決）**: 二段構え。
  1. `個人ｺｰﾄﾞ` が `staffs.personal_code` に存在する行だけ残す（他キャンパス・職員・無関係者を排除）。
  2. さらに `ｱﾙﾊﾞｲﾄ先①/②/③` のいずれかが `ノートテイク` の行（同一学生の別バイトを排除）。①固定ではないので①②③全走査。
- **主な列**: `個人ｺｰﾄﾞ / 氏名 / 処理日(yyyy/MM/dd) / 曜日 / 勤怠区分 / 出勤例外 / 退勤例外 / ﾒﾓ1 / ｱﾙﾊﾞｲﾄ交通費`、
  以降 ①②③ それぞれに `承認 / ｱﾙﾊﾞｲﾄ先 / 開始(HH:mm) / 終了(HH:mm) / 休憩(H:mm) / 時間(H:mm・実労) / 更新者氏名 / 更新日 / 更新時刻`。
- **照合方式への影響**: CSVに**時限（period）は無く実勤務時刻のみ**。
  機能Bは「日付＋時刻の重なり」で突合する（予定側は `periods` で時限→時刻に変換）。
- **ステータス更新**: CSV仕様は確定。実装は `staffs.personal_code` 追加とセットで着手可能。

### D3. 連絡先DBは職員のみアクセス可なら現設計でOK（本部承認）
- **決定（本部確認）**: 「職員しか連絡先データベース（contacts: email / phone / webhook_url）を確認できない」条件を満たせば、現在の2スプレッドシート分離設計で**プライバシー上問題なし**と本部から確認が取れた。
- **影響・対応（ハード要件）**:
  - 連絡先DBスプレッドシートの共有を**職員のみに技術的に制限**（リンク共有OFF・学生と共有しない）。実データ投入前の必須チェック。
  - アプリも**非職員クライアントに他人の連絡先項目を返さない**こと。新しいサーバー関数を書くとき要確認。
- **ステータス**: 承認済み。共有設定の実施は運用作業として残（backlog）。

### D4. スプレッドシートは非職員に一切公開不要
- **決定（設計確認）**: Web App を「職員として実行」でデプロイしているため、学生は**どのスプレッドシートにも権限ゼロ**でよい。学生に渡すのは **Web App の URL アクセス権（学内ドメイン限定）のみ**。
- **影響・対応**:
  - メインDB・連絡先DBとも**職員のみ共有**。
  - データ保護の責任は**コードの role 判定（requireStaff_ / getCurrentUser_）が全て担う**。職員専用処理のチェック漏れに注意。
- **ステータス**: 確認済み。

### D6. 物理アラート端末の仕様（案1）
- **決定**:
  - 用途は**職員向け**。**音＋光＋文字**で欠員を知らせる。
  - 端末候補：**M5Stack 系**（スピーカー・画面・LED・Wi-Fi 一体。M5StickC Plus2 等、¥3,000前後）。
  - 連携方式：端末が GAS Web App を**定期ポーリング**（クラウド→LAN内端末へ直接プッシュできないため）。
  - **アラート挙動（A方式）**:
    - 新しい欠員を検知 → **短いブザー1回（約1秒）→ 自動で鳴り止む**＋ **光・文字ON**。
    - 職員が**本体ボタンを押すと光・文字OFF**（「確認した」で消灯）。
    - さらに別の新しい欠員が来たら、また1回だけ鳴って点灯。
    - 「音＝新着イベント／光＝未確認の新着あり」。鳴り続けず、確認したら消えるので電気代もストレスも最小。
  - **GAS側エンドポイント**:
    - `doGet` に**トークン付きの軽量分岐**を1本追加。デバイスは `?token=（秘密文字列・スクリプトプロパティ保管）` で叩く。
    - 返すのは「**未対応欠員の件数 + 最新の欠員番号**」**のみ**（氏名等の個人情報は返さない＝D3と整合）。
    - 「確認した」状態は**デバイス側で保持**（GASへの書き込み不要、読み取り専用エンドポイントで済む）。
- **確認待ち**: オフィスに端末用 Wi-Fi があるか／音量・音色の希望／利用者が近くにいる時の音への配慮。
- **ステータス**: 仕様確定。GASエンドポイント実装はこれから。
