# 運用手順書（職員向け）

開発者がいなくてもこのシステムを**実環境で**運用できるようにするための手順書。
本編は **本番（実データ）** の手順。動作確認だけしたい場合は末尾の
[付録A：デモ環境](#付録aデモ環境動作確認用ダミーデータ) を使う。

| モード | セットアップ関数 | 中身 | 用途 |
|---|---|---|---|
| **本番（実環境）** | `setupSpreadsheetsEmpty` | 空（ヘッダーのみ・時限マスタだけ） | 実運用 |
| デモ（動作確認） | `setupSpreadsheets` | 架空のスタッフ・利用者・コマ入り | 試用・実証実験 |

## 0. 前提

- 大学の Google アカウント（Workspace）を使う。
- 操作する職員は **GAS プロジェクトの編集権限**を持つ（＝スクリプトプロパティ等の秘密情報を扱える人）。
- データはすべて大学 Google Workspace 内に置く（外部サービスへ個人情報を出さない）。
- **実データは Git にコミットしない**（スプレッドシート上にのみ存在させる）。

## 1. 本番セットアップ（実環境・最初に一度だけ）

### 1.1 空のDBを作る

1. GAS エディタで **`setupSpreadsheetsEmpty`** を実行する。
   → **メインDB** と **連絡先DB** が、ヘッダーのみ（＋時限マスタ）の空の状態で作られる。
   ※ `setupSpreadsheets`（ダミー入り）と間違えないこと。
2. ログに出る2つのスプレッドシートIDを控える。

> 📸 [スクショ] `setupSpreadsheetsEmpty` 実行後のログ（生成された2つのID）

### 1.2 スクリプトプロパティを登録する

「プロジェクトの設定 → スクリプト プロパティ」で登録する（**コードに直書きしない**）。

| キー | 値 |
|---|---|
| `SPREADSHEET_ID` | メインDB のID |
| `CONTACTS_SPREADSHEET_ID` | 連絡先DB のID |
| `CALENDAR_ID` | **実際の**共有カレンダーのID |
| `CHAT_WEBHOOK_URL` | 職員スペースの Incoming Webhook URL（→ 2章） |
| `DEVICE_TOKEN` | M5Stack 端末を使う場合のみ（任意） |

> 📸 [スクショ] スクリプトプロパティの登録画面

### 1.3 連絡先DBを「職員のみ」に共有する（重要）

連絡先DBには個人情報（メール・電話・Webhook）が入る。**スプレッドシートの共有設定で職員のみ**に制限する。
学生には共有しない（学生は画面経由でしかアクセスしないため、共有不要）。

> 📸 [スクショ] 連絡先DBの共有設定（職員のみ）

### 1.4 最初の職員（自分）を登録してログイン確認

空のDBには誰も登録されていないので、まず自分を1人入れる。

1. メインDB `staffs` に1行：`staff_id`（例 S001）／`name`／`role`＝**職員**（`skills`・`available_slots` は空でOK）
2. 連絡先DB `contacts` に同じ `staff_id`／`name`／`email`＝**自分の大学アドレス**
3. Web アプリURLを開く → シフト確認画面が出ればOK。
4. うまくいかないときは GAS の `whoAmI` でメール・staff_id・ロールが取れているか確認。

> 📸 [スクショ] ログイン後のシフト確認画面（この時点ではコマは空）

### 1.5 Web アプリをデプロイする

「デプロイ → 新しいデプロイ → ウェブアプリ」：

- **実行するユーザー：自分（デプロイした職員）**
- **アクセスできるユーザー：大学ドメインのアカウント**

発行URL（`…/exec`）が利用者に配るURL。
※ M5Stack 端末（`?device=alert`）を使う場合のみ、端末はGoogleログイン不可のためアクセスを「全員」にする
（その場合も各画面はコード側のロール判定で保護される）。

> 📸 [スクショ] デプロイ設定（実行＝自分／アクセス＝ドメイン）

## 2. Google Chat 個別通知の準備

通知は **Incoming Webhook** で送る。職員スペース用（全体・1個）とスタッフ各自用（個別・1人1個）がある。

- 職員スペース用 → スクリプトプロパティ `CHAT_WEBHOOK_URL`
- スタッフ個別用 → 連絡先DB `contacts` の `webhook_url` 列

> Webhook URL は「知っていれば誰でも投稿できる**秘密の鍵**」。必ず職員のみのシートに置き、コード/Gitに直書きしない。

### 2.1 Webhook の作り方（PCのブラウザで）

1. PC で [chat.google.com](https://chat.google.com) を開く（大学アカウント）。
2. 「スペース」→ ＋ →「スペースを作成」。名前は任意。自分だけでも可（※DMでは作れない）。
3. スペース名をクリック →「アプリと連携」。
4. 「Webhook を追加」→ 名前を付けて保存。
5. **Webhook URL をコピー**（`https://chat.googleapis.com/v1/spaces/…?key=…&token=…`）。

> 📸 [スクショ] 「アプリと連携 → Webhook を追加」画面
> 📸 [スクショ] Webhook URL 発行画面（※URL本体は隠して撮る）

### 2.2 テスト送信

```powershell
$url = "ここにWebhook URL"
Invoke-RestMethod -Method Post -Uri $url -ContentType 'application/json; charset=UTF-8' -Body (@{ text = "テスト通知です ✅" } | ConvertTo-Json)
```

職員スペース用はプロパティ登録後 GAS の `testNotify` でも確認できる。

> 📸 [スクショ] Chat に届いたテスト通知

### 2.3 学生スタッフへの展開

学生各自に 2.1 を案内し、できた URL を**連絡先フォーム**（→ 3.2）で集めて `contacts.webhook_url` に入れる。
未登録の人は通知時に「Webhook未登録」として安全にスキップされる（エラーにはならない）。

## 3. 実データの投入

回答者の**メールをキー**に `staff_id` と突合する。フォームの回答は自動でシートに溜まる。

### 3.1 スタッフ名簿 → `staffs`

- `staff_id`／`name`／`role`（職員 or 学生）／`skills`（`テイク`/`介助`/`テイク,介助`）を登録。
- `skills` 空欄は「全対応」として候補に出るため、運用前に入力推奨。

### 3.2 連絡先フォーム（一度だけ・変更時のみ）→ `contacts`

- 集める項目：氏名・メール（自動収集）・電話番号・**Chat Webhook URL**。
- 回答先は**職員のみ**のシート。`contacts` に反映。

### 3.3 空きコマフォーム（クォーター毎）→ `staffs.available_slots`

- 集める項目：氏名（or メール）・空きコマ（`月1,火3` 形式になるよう設計）。
- `available_slots` を上書き更新。

> 連絡先（静的・秘密）と空きコマ（クォーター毎に変動）は**フォームを分ける**。
> 毎クォーターの回答に電話・Webhookが混ざらず、秘密情報の露出を最小化できる。

### 3.4 時間割 → `courses`（シフト入力画面）

- **シフト入力（`?page=input`・職員）** から登録。利用者はプルダウン（新規は「＋新しい利用者を追加」）。
- 担当は「空き＋スキル」で自動的に絞られた候補から選ぶ。

### 3.5 カレンダー

- `CALENDAR_ID` に実際の共有カレンダーIDを設定（機能B＝勤怠照合の対象）。

---

## 4. クォーター更新フロー（年4回）

1. **空きコマフォーム**を配布 → `staffs.available_slots` を上書き反映。
2. 今期の支援対象授業を **シフト入力画面** で `courses` に登録。
3. 過去クォーターの `courses` は**消さない**（記録として残し、画面はクォーターで切替表示）。
4. スタッフの入退・スキル変更を `staffs`（`skills` 含む）に反映。連絡先変更があれば `contacts` も。

## 5. 日常運用

### 欠員が出たとき（基本は自動）

1. 欠勤者が **欠勤連絡（`?page=absence`）** で登録。
2. システムが候補（空き＋スキル）を抽出し、Chat で個別依頼＋職員へ通知。
3. **最初に承諾した人へ自動で確定**（先着・D1）。本人・他候補・職員へ結果通知。
4. 例外（誰も承諾しない等）のときだけ、職員が **欠員補充管理（`?page=manage`）** で
   「1人テイク」または「職員対応」に決着させる。

### シフトを直すとき

- 追加・削除は **シフト入力（`?page=input`）** から。欠員記録が紐づくコマは削除不可（記録保全）。

## 6. 動作確認（GASエディタから実行するテスト関数）

| 関数 | 確認できること |
|---|---|
| `whoAmI` | ログイン特定・ロール判定（メール→staff_id→role） |
| `testSheets` | スプレッドシートの読み書き（プロパティ設定の確認込み） |
| `testNotify` | 職員スペースへの Chat 送信（`CHAT_WEBHOOK_URL`） |
| `testVacancy` | 欠員の候補スクリーニング（空き＋スキル） |
| `testNotifyVacancy` | 最新の欠員で実際に候補へ通知（**実送信あり**） |
| `testRespond` | 回答〜確定まわりの確認 |
| `testDevicePoll` | M5Stack 端末用エンドポイントの応答 |
| `testCalendarConnection` | Google カレンダー連携（機能Bの基盤） |

> 実送信を伴う関数（`testNotify*`）は本物の Chat に届く。本番では送信先に注意。

## 8. トラブルFAQ

| 症状 | 原因 | 対処 |
|---|---|---|
| 「利用登録がありません」 | ログイン中のメールが `contacts` に無い | `contacts` に自分の `email` を登録。`whoAmI` で確認 |
| 職員用画面が「アクセス権限がありません」 | `staffs` の `role` が「職員」でない | 該当行の `role` を「職員」に |
| 通知が届かない（特定の人だけ） | その人の `webhook_url` 未登録／失効 | `contacts` の `webhook_url` を再登録（2章） |
| 通知が全く出ない | `CHAT_WEBHOOK_URL` 未設定／失効 | プロパティを確認し `testNotify` で疎通確認 |
| 「スクリプトプロパティ … が未設定」 | プロパティ未登録 | 1.2 の表を登録 |
| Webhook作成メニューが出ない | 管理者がWebhookを禁止 | Workspace管理者に「Incoming Webhook 許可」を依頼 |
| 時限の時刻/日付がずれる | `periods` がテキストでなく時刻型/日付型化 | 該当セルの表示形式を「書式なしテキスト」に |

## 付録A：デモ環境（動作確認用・ダミーデータ）

実データを使わず動きだけ見たいとき、または実証実験フェーズで使う。

1. GAS で **`setupSpreadsheets`** を実行（架空のスタッフ・利用者・コマ入りでDB作成）。
2. ID2件をプロパティに登録。
3. 連絡先DB `contacts` の `S001` の `email` を自分のアドレスに変更 → 職員としてログイン。
4. そのまま欠勤連絡 → 通知 → 回答 → 確定の流れを試せる。

> デモ環境と本番環境は**別のスプレッドシート**で運用すること（混ぜない）。
> 既存DBに列を足すマイグレーションは `migrateCoursesColumns()` / `migrateStaffsColumns()`。
