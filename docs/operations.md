# 運用手順書（職員向け）

開発者がいなくてもこのシステムを運用できるようにするための手順書。
初期セットアップ → 通知準備 → フォーム運用 → クォーター更新 → 日常運用 → 動作確認 → トラブル対処、の順にまとめる。

> **スクリーンショットについて**：本文中の `> 📸 [スクショ]` は、後で画像を差し込む箇所。
> 画像は `docs/img/` に置き、その行を `![説明](img/ファイル名.png)` に差し替える。
> 必要な画像の一覧は末尾の「[用意するスクリーンショット一覧](#用意するスクリーンショット一覧)」にまとめてある。

---

## 0. 前提

- 大学の Google アカウント（Workspace）を使う。
- 操作する職員は **GAS プロジェクトの編集権限**を持つ（＝スクリプトプロパティや秘密情報を扱える人）。
- データはすべて大学 Google Workspace 内に置く（外部サービスへ個人情報を出さない）。

---

## 1. 初期セットアップ（最初に一度だけ）

### 1.1 スプレッドシートを生成する

1. GAS エディタを開く。
2. 関数 `setupSpreadsheets` を実行する。
   → **メインDB** と **連絡先DB** の2つのスプレッドシートがダミーデータ入りで作られる。
3. 実行ログに出る2つのスプレッドシートIDを控える。

> 📸 [スクショ] GASエディタで `setupSpreadsheets` 実行後のログ（生成された2つのID）

### 1.2 スクリプトプロパティを登録する

GAS エディタの「プロジェクトの設定 → スクリプト プロパティ」で以下を登録する。
**コードに直書きしないこと。**

| キー | 値 |
|---|---|
| `SPREADSHEET_ID` | メインDB のスプレッドシートID |
| `CONTACTS_SPREADSHEET_ID` | 連絡先DB のスプレッドシートID |
| `CALENDAR_ID` | 連携する Google カレンダーのID |
| `CHAT_WEBHOOK_URL` | 職員スペースの Incoming Webhook URL（→ 2章） |
| `DEVICE_TOKEN` | M5Stack 端末用の認証トークン（任意・端末を使う場合） |

> 📸 [スクショ] スクリプトプロパティの登録画面

### 1.3 Web アプリとしてデプロイする

「デプロイ → 新しいデプロイ → 種類：ウェブアプリ」で設定する。

- **実行するユーザー：自分（デプロイした職員）**
- **アクセスできるユーザー：大学ドメインのアカウント**

> ⚠️ M5Stack 端末（`?device=alert`）を使う場合のみ、端末はGoogleログインできないため
> アクセスを「全員」にする必要がある。その場合も各画面はコード側のロール判定で保護される。

発行された Web アプリURL（`…/exec`）を控える。これが利用者に配るURL。

> 📸 [スクショ] デプロイ設定（実行ユーザー＝自分／アクセス＝ドメイン）

### 1.4 自分でログインできるか確認する

1. 連絡先DB `contacts` シートの自分の行の `email` を、自分の大学アドレスに書き換える。
2. Web アプリURLを開く → シフト確認画面が出ればOK。
3. うまくいかないときは GAS で `whoAmI` を実行し、メール・staff_id・ロールが取れているか確認する。

> 📸 [スクショ] シフト確認画面が表示された状態（ログイン成功）

## 2. Google Chat 個別通知の準備

代行依頼などの通知は **Incoming Webhook** で送る。職員スペース用（全体）と、スタッフ各自用（個別）がある。

- **職員スペース用**（1個）→ スクリプトプロパティ `CHAT_WEBHOOK_URL`
- **スタッフ個別用**（1人1個）→ 連絡先DB `contacts` の `webhook_url` 列

> Webhook URL は「知っていれば誰でもそのスペースに投稿できる**秘密の鍵**」。
> 必ず職員のみアクセス可のシート（連絡先DB）に置き、コードやGitに直書きしない。

### 2.1 Webhook の作り方（PCのブラウザで）

1. PC で [chat.google.com](https://chat.google.com) を開く（大学アカウント）。
2. 「スペース」→ ＋ →「スペースを作成」。名前は任意（例：シフト管理通知）。自分だけでも可。
   - ※ 1対1のDMではWebhookを作れない。必ず**スペース**を作る。
3. スペース名をクリック →「アプリと連携」。
4. 「Webhook を追加」→ 名前を付けて保存。
5. 生成された **Webhook URL をコピー**（`https://chat.googleapis.com/v1/spaces/…?key=…&token=…`）。

> 📸 [スクショ] 「アプリと連携 → Webhook を追加」の画面
> 📸 [スクショ] Webhook URL が発行された画面（※URL本体は隠して撮る）

### 2.2 テスト送信

コピーしたURLが届くか、PowerShell で確認できる：

```powershell
$url = "ここにWebhook URL"
Invoke-RestMethod -Method Post -Uri $url -ContentType 'application/json; charset=UTF-8' -Body (@{ text = "テスト通知です ✅" } | ConvertTo-Json)
```

職員スペース用は、URLをプロパティに入れた後 GAS の `testNotify` でも確認できる。

> 📸 [スクショ] Chat に届いたテスト通知

### 2.3 学生スタッフへの展開

学生各自に上記 2.1 の手順を案内し、できた URL を**連絡先フォーム**（→ 3章）で集め、
連絡先DB `contacts` の各人の `webhook_url` 列に入れる。
未登録の人は通知時に「Webhook未登録」として安全にスキップされる（エラーにはならない）。

## 3. フォーム運用

Google Form の回答は自動でスプレッドシートに溜まる。回答者の**メールをキー**に `staff_id` と突合する。

### 3.1 連絡先フォーム（一度だけ・変更時のみ）

- 集める項目：氏名・メール（自動収集）・電話番号・**Chat Webhook URL**
- 回答先は**職員のみアクセス可**のシートにする（＝連絡先DBの方針）。
- メール・電話・Webhook を `contacts` に反映する。

### 3.2 空きコマフォーム（クォーター毎）

- 集める項目：氏名（or メール）・空きコマ（`月1,火3` 形式になるよう設計）
- 反映先：`staffs` シートの `available_slots`（上書き更新）。

> 連絡先（静的・秘密）と空きコマ（クォーター毎に変動）は**フォームを分ける**。
> こうすると毎クォーターの回答に電話・Webhookが混ざらず、秘密情報の露出を最小化できる。

## 4. クォーター更新フロー（年4回）

龍谷大学はクォーター制。クォーター開始時に以下を行う。

1. **空きコマフォーム**を配布 → 回答を `staffs.available_slots` に上書き反映。
2. 今期の支援対象授業を **シフト入力画面（`?page=input`）** で `courses` に登録。
   - 利用者はプルダウン（新規は「＋新しい利用者を追加」）。
   - 担当は「空き＋スキル」で自動的に絞り込まれた候補から選ぶ。
3. 過去クォーターの `courses` は**消さない**（記録として残す。画面はクォーターで切替表示）。
4. スタッフの入退・スキル変更があれば `staffs`（`skills` 列含む）を更新。

## 5. 日常運用

### 欠員が出たとき（基本は自動）

1. 欠勤者が **欠勤連絡（`?page=absence`）** で登録。
2. システムが候補（空き＋スキル）を抽出し、Chat で個別依頼＋職員へ通知。
3. **最初に承諾した人へ自動で確定**（先着・D1）。本人・他候補・職員へ結果通知。
4. 例外（誰も承諾しない等）のときだけ、職員が **欠員補充管理（`?page=manage`）** で
   「1人テイク」または「職員対応」に決着させる。

### シフトを直すとき

- 追加・削除は **シフト入力（`?page=input`）** から。欠員記録が紐づくコマは削除不可（記録保全）。

## 6. 動作確認（GASエディタから実行するテスト関数）

| 関数 | 確認できること |
|---|---|
| `whoAmI` | ログイン特定・ロール判定（メール→staff_id→role） |
| `testSheets` | スプレッドシートの読み書き（プロパティ設定の確認込み） |
| `testNotify` | 職員スペースへの Chat 送信（`CHAT_WEBHOOK_URL`） |
| `testVacancy` | 欠員の候補スクリーニング（空き＋スキル） |
| `testNotifyVacancy` | 最新の欠員で実際に候補へ通知（実送信あり） |
| `testRespond` | 回答〜確定まわりの確認 |
| `testDevicePoll` | M5Stack 端末用エンドポイントの応答 |
| `testCalendarConnection` | Google カレンダー連携（機能Bの基盤） |

> 実送信を伴う関数（`testNotify*`）は、本物の Chat に届く点に注意。テスト用スペースで試すこと。

## 7. トラブルFAQ

| 症状 | 原因 | 対処 |
|---|---|---|
| 「利用登録がありません」 | ログイン中のメールが `contacts` に無い | `contacts` の自分の行の `email` を実アドレスに。`whoAmI` で確認 |
| 職員用画面が「アクセス権限がありません」 | `staffs` の `role` が「職員」でない | `staffs` の該当行の `role` を「職員」に |
| 通知が届かない（特定の人だけ） | その人の `webhook_url` 未登録／URL失効 | `contacts` の `webhook_url` を確認・再登録（2章） |
| 通知が全く出ない | `CHAT_WEBHOOK_URL` 未設定／失効 | プロパティを確認し `testNotify` で疎通確認 |
| 「スクリプトプロパティ … が未設定」 | プロパティ未登録 | 1.2 の表を登録 |
| Webhook作成メニューが出ない | 管理者がWebhookを禁止 | Workspace管理者に「Incoming Webhook 許可」を依頼 |
| 時限の時刻がおかしい/日付がずれる | `periods` がテキストでなく時刻型/日付型化 | 該当セルの表示形式を「書式なしテキスト」に |
