# 構築・引き継ぎ手順（管理者向け・最初に一度だけ）

このシステムを立ち上げて職員に「**URLを1本渡すだけ**」の状態にするための手順。
ここに書く作業は**構築者（開発担当）が一度だけ**行う。職員の日常運用は [`operations.md`](operations.md) を参照。

> ⚠️ **所有アカウントが最重要**：GASのデプロイとトリガーは「作成したアカウント」で動く。
> 個人/学生アカウントで構築すると、卒業・退職でアカウントが消えた瞬間に全停止する。
> **支援室（部署）のGoogleアカウント、または恒久的な職員アカウントで所有・デプロイ・トリガー設置**すること。
> 構築は代行してよいが、最終的な所有者を部署アカウントにする。

---

## 0. 役割分担（D29）

**この手順は職員アカウントで実行します。** 誰が何を持つかを最初に固定しておくこと。

| | 担当 |
|---|---|
| スプレッドシート2つの所有 | **職員アカウント**（`setupSpreadsheetsEmpty` を職員が実行する） |
| 開発者への共有 | 編集者として（検証で書き込むため） |
| GASプロジェクトの編集・`clasp push` | 開発者 |
| **最終デプロイ** | **職員アカウントのみ** |
| `installTriggers()` | **職員アカウント** |
| 開発者の動作確認 | `/dev`（デプロイをテスト） |

Web App は `executeAs: USER_DEPLOYING`＝**最後にデプロイした人として動く**ため、
実行アカウントとスプレッドシートの所有者を一致させる必要がある。
**職員以外（開発者・M5Stack担当を含む）はデプロイしないこと。**

> ⚠️ **引き継ぎは途中**：本番の2つのスプレッドシートとGASプロジェクトは開発者（学生）アカウント所有
> だったため、**2026-09-14 に職員アカウントへオーナー移管した**（6.2 の手順1・2 完了）。
> **職員による再デプロイと `installTriggers()` の再実行（手順5・6）がまだ**で、
> 実行アカウントとトリガーの実行者は今も開発者のまま。このままでは
> 開発者のアカウントが停止された時点で全停止する。
> **[6章](#6-開発者アカウントからの引き継ぎ卒業異動で担当が抜けるとき)の残りを実施すること。**

## 1. 本番セットアップ

### 1.1 空のDBを作る
1. GAS エディタで **`setupSpreadsheetsEmpty`** を実行（ヘッダーのみ＋時限マスタで2つのDBを生成）。
   ※ `setupSpreadsheets`（ダミー入り）と間違えないこと。
2. ログに出る2つのスプレッドシートIDを控える。

### 1.2 スクリプトプロパティを登録
「プロジェクトの設定 → スクリプト プロパティ」で登録（**コードに直書きしない**）。

| キー | 値 |
|---|---|
| `SPREADSHEET_ID` | メインDB のID |
| `CONTACTS_SPREADSHEET_ID` | 連絡先DB のID |
| `CALENDAR_ID` | 実際の共有カレンダーのID |
| `CHAT_WEBHOOK_URL` | 職員スペースの Incoming Webhook URL（→ 3章） |
| `DEVICE_TOKEN` | M5Stack 端末を使う場合のみ（任意） |

### 1.3 連絡先DBを「職員のみ」に共有
連絡先DB（メール・電話・Webhook）は**スプレッドシートの共有設定で職員のみ**に制限。学生には共有しない。

### 1.4 最初の職員を登録
空のDBには誰もいないので、まず1人入れる。
- メインDB `staffs`：`staff_id`／`name`／`role`＝**職員**
- 連絡先DB `contacts`：同じ `staff_id`／`name`／`email`＝その職員の大学アドレス

### 1.5 Web アプリをデプロイ
「デプロイ → 新しいデプロイ → ウェブアプリ」：
- **実行するユーザー：自分（＝部署アカウント）**
- **アクセスできるユーザー：大学ドメインのアカウント**

発行URL（`…/exec`）が**職員・学生に配るURL**。
※ M5Stack 端末（`?device=alert`）を使う場合のみアクセスを「全員」にする（画面はコード側のロール判定で保護）。

## 2. データ投入の自動化（職員の手作業をなくす）

職員がスプレッドシートを触らずに済むよう、データはフォーム＋トリガーで流し込む。

- **連絡先フォーム**（氏名・メール・電話・Chat Webhook URL）→ `contacts`
- **空きコマフォーム**（氏名 or メール・空きコマ `月1,火3` 形式）→ `staffs.available_slots`
- 各フォームに `onFormSubmit` トリガーを設置すると、**送信した瞬間に自動でシートへ反映**される
  （※取り込み関数・トリガーは今後実装。未設置の間は構築者が反映を代行する）

> 連絡先（静的・秘密）と空きコマ（クォーター毎に変動）は**フォームを分ける**。

> ### ⚠️ `clasp push` だけでは `/exec` に反映されない
>
> **push はコードを更新するだけで、公開URL（`/exec`）が配信するのは「デプロイしたバージョン」です。**
> デプロイを更新しない限り、職員・学生の画面は古いままになります。エラーは出ません。
>
> 確認と更新はこうします。
>
> ```
> npx clasp deployments        # @HEAD（テスト用）と @46 のようにバージョンが出る
> ```
>
> - **検証中だけ最新を見たい** … GASエディタ「デプロイ → デプロイをテスト」の `/dev` URL。
>   常に最新を配信します。ただし**スクリプトの編集権限があるアカウントしか開けません**
>   （学生アカウントでの通し確認には使えません）。
> - **本番URLを最新にする** … 「デプロイ → デプロイを管理 → 鉛筆アイコン →
>   バージョン『新しいバージョン』→ デプロイ」。`/exec` の URL は変わりません。
>   **新規デプロイを作らないこと**（URLが変わり、配布済みのリンクが古いコードを指したままになります）。
>
> 画面の変更が反映されないときは、ブラウザのキャッシュ（Ctrl+Shift+R）より先にここを疑ってください。
> 時間割は `?page=home&debug=1` で開くと画面下に診断が出ます。**この枠が出なければ古いコードです。**

> ### ⚠️ デプロイした人が「システムの実行者」になる
>
> `appsscript.json` は `"executeAs": "USER_DEPLOYING"` なので、**Web App は最後にデプロイした人の
> アカウントとして動きます。** その人がスプレッドシートを開けないと、全員が
> **「リクエストされたドキュメントにアクセスする権限がありません」**で止まります。
>
> **2026-09-12 に実際に起きました。** 別担当者が M5Stack の検証のために版を作って本番デプロイを
> 更新したところ、実行アカウントがその人に替わり、スプレッドシート（別アカウント所有）を開けなくなって
> 全画面が落ちました。コードは一切壊れておらず、原因はデプロイ主の交代だけでした。
>
> 切り分けは `showConfig()`（Tests.gs）で一発です。**「実行権限」に出るアドレス**が、
> スプレッドシートを開ける人かどうかを見てください。
>
> **こうしておくこと：**
> - GASプロジェクトとスプレッドシート2つを**部署アカウント所有**にし、**デプロイは部署アカウントからだけ**行う
> - 複数人が触るなら、**スプレッドシートを各担当者にも共有**しておく（誰がデプロイしても動く状態にする）
> - 同じデプロイを複数人で更新し合わない。直す前に一声かける

## 2.5 時間トリガーを登録する（締切検知・D22）

代行が決まらないまま締切（授業開始30分前）に達した欠員を検知し、職員へ「決着してください」を
通知する処理は**時間トリガー**で動く。これを入れないと、誰も承諾しなかった欠員について
**通知が一切出ない**（欠勤連絡の時点でしか締切を判定できないため）。

1. GASエディタで `migrateAddVacancyCloseNotifiedAt()` を1回実行する
   （既存DBに `vacancies.close_notified_at` 列を足す。新規 `setupSpreadsheetsEmpty` なら不要）。
2. `installTriggers()` を実行する（10分ごとに `closeExpiredRecruits` が走るようになる）。
3. `listTriggers()` で登録内容と**実行者アカウント**を確認する。

> ⚠️ **トリガーはインストールした人のアカウントで動く**。Web App の「実行するユーザー」とは
> **別管理**なので、担当者が代わったら新しい担当者が `installTriggers()` を実行し直すこと。
> 片方だけ引き継ぐと「画面は動くのに締切通知だけ来ない」という気づきにくい壊れ方をする。

## 2.6 空きコマの業務別分離と移動介助の枠を入れる（D32・D33）

既存DBを使っている場合だけ必要（新規 `setupSpreadsheetsEmpty()` なら最初から入っている）。

1. **`clasp push` を先に済ませる**（エディタから実行できるのは push 済みのコードだけ）。
2. GASエディタで **`migrateSlotsAndMovePeriods()`** を1回実行する。
   内部で4つを正しい順番で呼ぶ（列を足してから行を挿入する必要があるため）。

   | 順 | 関数 | 何をするか |
   |---|---|---|
   | 1 | `migrateAddPeriodSupportTypes()` | `periods.support_types`（空＝全業務） |
   | 2 | `migrateAddPeriodLabel()` | `periods.label`（空＝「n限」） |
   | 3 | `migrateAddMovePeriods()` | 移動介助の行を**1限の前と授業のあいだへ挿入** |
   | 4 | `migrateAddAssistSlots()` | `staffs.assist_slots`（介助の空きコマ） |

3. 実行ログの確認事項を見る。あわせてシートも目で確かめる。
   - `periods` の並びが **「移動介助 → 1限 → 移動介助 → 2限 → …」** になっているか。
     **行の順番がそのまま時間割の並び順**になる。先頭は1限の前（登校の付き添い）の枠
   - `staffs.assist_slots` に `available_slots` の内容が**コピーされている**か

> ⚠️ **`assist_slots` を空のまま運用しない。** 空の人は**介助の代行候補に一度も出てこない**。
> エラーは出ず「なぜか誰にも通知が飛ばない」としてしか現れないので、移行直後に必ず確認する。
> 移行後は各自がマイページの介助タブで実態に合わせて直す。

> **実行する人**：スクリプトの編集権限があり、スプレッドシート2つを開けるアカウントなら誰でもよい。
> エディタからの実行は「デプロイした人」ではなく**実行した人**として動くので、
> デプロイ担当（職員・D29）でなくても構わない。
>
> **`clasp run` は使えない**。実行APIを使うには `appsscript.json` に `executionApi` を足して
> 本番のマニフェストを push し直し、標準GCPプロジェクトを紐付け、`clasp login --creds` を
> 別途設定する必要がある。1回のマイグレーションのために本番のマニフェストを触る価値は無い。

## 3. 職員スペースの Webhook（全体通知用）

1. PC で [chat.google.com](https://chat.google.com) → スペースを作成（職員が見るスペース）。
2. スペース名 →「アプリと連携」→「Webhook を追加」→ 名前を付けて保存 → URLをコピー。
3. そのURLをスクリプトプロパティ `CHAT_WEBHOOK_URL` に登録。
4. GAS の `testNotify` で疎通確認（Chatに届けばOK）。

> スタッフ個別のWebhookは学生本人が作成し、連絡先フォームで集める（学生向け案内は operations.md 付録）。

## 6. 開発者アカウントからの引き継ぎ（卒業・異動で担当が抜けるとき）

> ⚠️ **「共有した」は「引き継いだ」ではない。** 共有はアクセス権を配るだけで、
> ファイルの所有者は作った人のままになる。所有アカウントが**停止された時点で**
> （削除を待たずに）Web App もトリガーも止まる。**担当が抜ける前に必ずこの章を実行する。**

### 6.1 いま誰が何を持っているかを確認する

| 見るもの | 確認方法 | あるべき状態 |
|---|---|---|
| スプレッドシート2つの所有者 | Drive で各ファイルを右クリック →「共有」→ オーナー表示 | 職員（部署）アカウント |
| GASプロジェクトの所有者 | Drive でスクリプトファイルの共有を開く | 職員（部署）アカウント |
| Web App の実行アカウント | `showConfig()`（Tests.gs）の「実行権限」 | 職員（部署）アカウント |
| トリガーの実行者 | `listTriggers()`（Triggers.gs） | 職員（部署）アカウント |
| カレンダーの所有者 | Googleカレンダーの設定 → そのカレンダー → 権限 | 職員（部署）アカウント／大学の共有カレンダー |
| Chatスペースの管理者 | スペース → メンバーを管理 | 職員が複数名 |

1つでも開発者アカウントなら、6.2 を実行する。

### 6.2 移す順番

**引き継ぎ先は「支援室（部署）のGoogleアカウント」が望ましい。** 個人の職員アカウントに移すと、
その職員の異動・退職で同じ事故がもう一度起きる。部署アカウントを作れないか先に大学へ確認すること。

順番を守る。**所有権を移す前に再デプロイすると、職員がDBを開けない状態で実行者だけ替わり、全画面が止まる。**

1. **スプレッドシート2つのオーナーを移す**
   Drive → 右クリック →「共有」→ 職員を**編集者**にする → 職員の行のメニューから**「オーナーに変更」**。
   移管後も旧オーナーは編集者として残るので、開発者の検証は続けられる。
2. **GASプロジェクトを個人アカウントから外す**
   このプロジェクトは**スタンドアロン**（スプレッドシートに紐づいていない独立したDriveファイル）なので、
   シートを移管しても**スクリプトは移らない**。次のA→B→Cの順で試す。
   スクリプトプロパティ（`SPREADSHEET_ID` 等）はプロジェクトに紐づくので、**AとBなら引き継がれる**。

   - **A. 共有ドライブへ移動する（最優先）**
     Drive でスクリプトファイルを共有ドライブへドラッグする。共有ドライブのファイルは**組織所有**になり、
     個人アカウントの生死に依存しなくなる＝この問題自体が消える。スクリプトIDもURLも変わらない。
     共有ドライブが無ければ大学の管理者に作成を依頼する。
   - **B. Drive でオーナーを変更する**
     スクリプトファイルを右クリック →「共有」→ 職員を編集者にする → 職員の行のメニューに
     **「オーナーに変更」が出れば選ぶ**。同一ドメイン内のみ。スクリプトIDもURLも変わらない。
     ⚠️ **Apps Script ファイルではこの項目が出ないことがある。** 出なければAかCへ回る。
     「出るはず」で粘らず、実際にメニューを開いて確かめること。
   - **C. 職員アカウントでコピーを作る（最終手段）**
     AもBも不可のときだけ。**コストが大きいので必ず最後に検討する**：
     - **スクリプトプロパティはコピーされない** → 5つ全部を手で入れ直す（1.2 の表）
     - **デプロイもコピーされない** → 新規デプロイになり **`/exec` URL が変わる**
       → 職員・学生・M5Stack中継へ配ったURLを全部配り直す
     - `.clasp.json` の `scriptId` も変わる → 後任の開発者に伝え直す
     - 旧プロジェクトは**デプロイを削除してから**放置する（二重稼働を防ぐ）
3. **カレンダーを確認する**
   `CALENDAR_ID` が開発者個人のカレンダーなら、職員所有のカレンダーを用意して予定を移し、
   プロパティを差し替える（カレンダーはオーナー変更ができないため、作り直しになる）。
4. **Chatスペースに職員の管理者を追加する**
   Webhook URL はスペースに紐づくので、スペースが残ればURLは使い続けられる。
   開発者しか管理者がいない状態にしない。
5. **職員アカウントで再デプロイする**
   「デプロイ → デプロイを管理 → 鉛筆 → 新しいバージョン → デプロイ」。
   **新規デプロイは作らない**（URLが変わり、配布済みのリンクが古いコードを指す）。
   これで `executeAs: USER_DEPLOYING` の実行者が職員に替わる。
6. **職員アカウントで `installTriggers()` を実行する** → `listTriggers()` で実行者が職員になっていることを確認。
7. **開発者アカウントで `removeTriggers()` を実行する**
   開発者名義のトリガーが残っていると**同じ処理が二重に走る**。6の後に必ず消す。

> ⚠️ **5と6は別管理**。片方だけやると「画面は動くのに締切通知だけ来ない」という気づきにくい壊れ方をする。
